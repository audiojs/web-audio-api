Migration, Browser, Node

Browser to Node

Web Audio nodes, connections, automation, and scheduling stay in one runtime-neutral function. Permissions and I/O belong to thin adapters.

Graph core

export function buildGraph(ctx, { frequency = 440 } = {}) {
  const osc = ctx.createOscillator()
  const gain = ctx.createGain()
  osc.frequency.value = frequency
  gain.gain.value = 0.25
  osc.connect(gain).connect(ctx.destination)
  osc.start()
  return { osc, gain }
}

No window, DOM, filesystem, process, speaker, or microphone appears here.

Browser adapter

import { buildGraph } from './graph.js'

button.addEventListener('click', async () => {
  const ctx = new AudioContext()
  await ctx.resume()
  buildGraph(ctx)
})

The click supplies the browser’s required user gesture. The graph uses the native browser engine.

Node adapter

import { AudioContext } from 'web-audio-api'
import { buildGraph } from './graph.js'

const ctx = new AudioContext()
await ctx.resume()
buildGraph(ctx)

process.on('SIGINT', () => ctx.close())

WAA supplies speaker output by default. Pass a writable as sinkId when PCM should enter a pipeline instead.

Checklist

  • Move graph creation into a function that accepts a context.
  • Import constructors directly or install the polyfill for browser-oriented libraries.
  • Call resume() explicitly; close the context when the process is done.
  • Replace DOM media elements with decoded buffers, streams, or custom PCM tracks.
  • Use OfflineAudioContext for deterministic output and tests.
  • Keep low-latency assumptions behind a measured integration test.
