Audio testing in CI

Render the production Web Audio graph into memory. No browser, speaker, virtual audio device, or native binding is required.

Example test

The assertion below checks a useful invariant without depending on one engine’s last floating-point bit.

import assert from 'node:assert/strict'
import { OfflineAudioContext } from 'web-audio-api'

function buildGraph(ctx) {
  const osc = ctx.createOscillator()
  const gain = ctx.createGain()
  osc.frequency.value = 440
  gain.gain.value = 0.25
  osc.connect(gain).connect(ctx.destination)
  osc.start(0)
  osc.stop(1)
}

const rate = 44100
const ctx = new OfflineAudioContext(1, rate, rate)
buildGraph(ctx)
const audio = await ctx.startRendering()

let peak = 0
for (const sample of audio.getChannelData(0))
  peak = Math.max(peak, Math.abs(sample))

assert.equal(audio.length, rate)
assert.equal(audio.sampleRate, rate)
assert.ok(peak > 0.24 && peak <= 0.25)

GitHub Actions

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm test

No ALSA null device, browser launch, or sound-server package is part of the job.

I/O boundaries

Test files, microphones, streams, and codecs with fixtures at their adapter. Test the graph itself with an OfflineAudioContext. That separation is what lets one core run in Browser, CLI, and CI.
