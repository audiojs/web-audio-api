Audio testing in CI

Render the production Web Audio graph into memory. No browser, speaker, virtual audio device, or native binding is required.

Example test

The assertions below, from @audio/assert, check useful invariants without depending on one engine’s last floating-point bit. Each throws a plain Error, so they work under node:test, tape, tap, vitest, or bare scripts alike.

import { OfflineAudioContext } from 'web-audio-api'
import { frequency, peak, unclipped, dc } from '@audio/assert'

function buildGraph(ctx) {
  const osc = ctx.createOscillator()
  const gain = ctx.createGain()
  osc.frequency.value = 440
  gain.gain.value = 0.25
  osc.connect(gain).connect(ctx.destination)
  osc.start(0)
  osc.stop(1)
}

const rate = 44100
const ctx = new OfflineAudioContext(1, rate, rate)
buildGraph(ctx)
const audio = await ctx.startRendering()

frequency(audio, rate, 440)
peak(audio, 0.25, 0.01)
unclipped(audio)
dc(audio, 0.01)

Avoid snapshotting an entire buffer unless bit identity is the requirement. A domain assertion explains the regression better.

GitHub Actions

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm test

No ALSA null device, browser launch, or sound-server package is part of the job.

I/O boundaries

Test files, microphones, streams, and codecs with fixtures at their adapter. Test the graph itself with an OfflineAudioContext. That separation is what lets one core run in Browser, CLI, and CI.
