Tone.js in Node

Give Tone the browser globals it expects, then run its familiar synths and scheduling against WAA.

Realtime output

import 'web-audio-api/polyfill'
const Tone = await import('tone')

const ctx = new AudioContext()
await ctx.resume()
Tone.setContext(ctx)

const synth = new Tone.Synth().toDestination()
synth.triggerAttackRelease('C4', '8n')

Import order is load-bearing. Tone’s standardized-audio-context dependency inspects window.AudioParam and related constructors while the module loads.

Import order

Static ESM imports are evaluated before the rest of the module body. This would load Tone before the polyfill has installed Web Audio globals.

// This order is not guaranteed by source position:
import 'web-audio-api/polyfill'
import * as Tone from 'tone'

If you want a static Tone import, install the polyfill from Node’s command line:

node --import web-audio-api/polyfill app.js

Offline testing

import assert from 'node:assert/strict'
import 'web-audio-api/polyfill'
const Tone = await import('tone')

const rate = 44100
const ctx = new OfflineAudioContext(1, rate, rate)
Tone.setContext(ctx)

const synth = new Tone.Synth().toDestination()
synth.triggerAttackRelease('C4', '8n')
const audio = await ctx.startRendering()

let peak = 0
for (const sample of audio.getChannelData(0))
  peak = Math.max(peak, Math.abs(sample))
assert.ok(peak > 0.1)

This exact integration is covered by the repository test suite.
