FAQ

Is it fast enough for realtime?

For simple graphs, yes: every measured scenario renders hundreds of times faster than realtime. The native Rust binding stays 1.5–3× quicker; AudioWorklet execution is currently synchronous, so production low-latency work remains the boundary.

How do speakers and mics work?

@audio/speaker provides the default output device. Microphone examples use the optional @audio/mic adapter, then feed PCM into a MediaStreamTrack. You can also set sinkId to any Node writable stream. Speaker output works on Node, Deno, Bun, and through the browser's own Web Audio; the microphone adapter is verified on Node.

Which formats can it decode?

decodeAudioData() uses @audio/decode: the format is detected and its codec loaded on demand, without FFmpeg or native bindings, so coverage does not vary by browser or operating system.

Compressed
MP3, AAC, Ogg Vorbis, Opus, WMA, AMR, Musepack, QOA
Lossless
FLAC, ALAC, WavPack, APE, TTA
Uncompressed
WAV, AIFF, CAF, DSF and DFF (DSD)
Surround
AC-3, E-AC-3, DTS
Video containers
MP4, M4A, MOV, M4V, 3GP, WebM, MKV, AVI: the audio track is extracted
Tracker modules
MOD, XM, S3M, IT

Codec packages carry their own licences.

How heavy is it?

160 KB gzipped from npm, with the engine, its typings, and all 46 examples inside, so npx web-audio-api metronome plays with nothing else installed. Installed, the codec packages behind @audio/decode bring it to about 26 MB on disk; each codec loads only when its format is decoded.

From a CDN it is about 90 KB over the wire: plain ESM that runs in a browser tab or a Web Worker, where no Web Audio exists.

import { OfflineAudioContext } from 'https://esm.sh/web-audio-api'
Do Tone.js and other libraries work?

Yes. The polyfill installs the Web Audio globals, so a library that reaches Web Audio only through them runs unchanged; Tone.js is the one the test suite covers. Install the globals before dynamically importing it, so its browser checks see the constructors.

import 'web-audio-api/polyfill'
const Tone = await import('tone')

const ctx = new AudioContext()
await ctx.resume()
Tone.setContext(ctx)
new Tone.Synth().toDestination()
  .triggerAttackRelease('C4', '8n')

Or start Node with the polyfill already loaded, node --import web-audio-api/polyfill app.js, and a static import * as Tone from 'tone' works.

Also checked through the polyfill: tunajs effects, smplr with its soundfonts fetched over the network, and Pizzicato once its context is resumed. soundfont-player and Howler reach for XMLHttpRequest, navigator, and HTML5 Audio, which Node does not have.

How do I test audio in CI?

Render in memory, then assert samples, peaks, RMS, spectra, duration, or channel count. No audio device is opened.

import assert from 'node:assert/strict'
import { OfflineAudioContext } from 'web-audio-api'

const ctx = new OfflineAudioContext(1, 44100, 44100)
const osc = ctx.createOscillator()
osc.connect(ctx.destination)
osc.start()

const audio = await ctx.startRendering()
assert(audio.getChannelData(0).some(Boolean))

@audio/assert adds the domain checks: frequency, peak, unclipped, dc, each throwing a plain Error under any test runner.

Can it run without speakers?

Yes. OfflineAudioContext renders without opening @audio/speaker. A realtime context can instead send PCM to a writable stream through sinkId.

import { OfflineAudioContext } from 'web-audio-api'

const ctx = new OfflineAudioContext(2, 44100, 44100)
// build the same graph here
const audio = await ctx.startRendering()
Does it support AudioWorklets?

Yes. Modules can be registered by URL, data URL, Blob URL, or an inline callback in Node. Worklets currently execute synchronously rather than on an isolated realtime thread.

import { AudioContext, AudioWorkletNode } from 'web-audio-api'

const ctx = new AudioContext()
await ctx.resume()
await ctx.audioWorklet.addModule(scope => {
  class PassThrough extends scope.AudioWorkletProcessor {
    process(inputs, outputs) {
      outputs[0][0].set(inputs[0][0] || [])
      return true
    }
  }
  scope.registerProcessor('pass-through', PassThrough)
})

const node = new AudioWorkletNode(ctx, 'pass-through')

What differs from a browser?

The I/O boundary. Everything else follows the same specification: the graph API, the 128-frame render quantum, automation, and node behavior.

AspectBrowserNode
Outputdestination plays through the device@audio/speaker by default, or any writable stream via sinkId
MicrophonegetUserMedia()@audio/mic feeding a MediaStreamTrack; the polyfill installs getUserMedia()
Filesfetch(), then the browser’s codecsfs, then @audio/decode
Media elementsMediaElementAudioSourceNode plays a tagA silent stub; decode to a buffer instead
AudioWorkletIts own realtime threadSynchronous, on the same thread
Lifecycleresume() inside a user gestureresume() at will; close() when the process is done

Keep graph construction in one function that takes a context; the browser adapter supplies the user gesture and the native context, the Node adapter imports the package and closes the context when the process is done.
